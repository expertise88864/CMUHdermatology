# 代表性使用流程量測與月曆重畫改善

本次以已完成補審與交付的 `8ba1840f9bc74a70f8221c85218c6daabd78ff83`
為基準，在 Windows 11、Python 3.13.1、OR-Tools 9.15.6755 下順序量測。
資料均為匿名合成案例，設定與匯出檔只寫入隔離暫存目錄；不連接 HIS、郵件、
打卡或正式資料。以下數值不是院內電腦效能或醫療驗收結果。

RosterService 求解與有 revision／fingerprint 檢查的套用流程；門診醫師配置
與純求解工具不同，兩者不是同一份輸入。

Excel 與 Word 的全部日班格逐格讀回比對，Word 另核對 31 天 R／VS 資料，
PDF 核對所有經原有字型清理後的章節文字。R／VS 是匯出用匿名內容，未宣稱
符合正式值班計畫。讀回檢查不包含在匯出耗時內，匯出後原月檔不變。
量測所需 PDF 讀取器使用開發工具已有套件，沒有新增程式執行依賴。

## 採納範圍：相同月曆內容不重建卡片

原本鎖定／解鎖與重新整理都銷毀並重建整月卡片。現在僅當月份、日班內容、
假日、今日日期、定案狀態及 Tk 縮放比例都相同時，保留已完成的月曆卡片。
列表、警告、統計與權威資料仍照常重新讀取；選單開啟時仍讀取當下鎖定狀態。
任何顯示條件改變都重新建構。輸入快照以深複製保存，重畫失敗先使快照失效，
避免部分畫面被誤認為已完整呈現。每個分頁只保存最後一次成功的狀態。

正式實作採五組交錯順序比較，每個版本各開新程序；每個案例與操作保留六筆，
第一筆另列，以下是五組暖樣本中位數的中位數。基準使用上述基準 SHA 的原始
renderer，其餘程式與輸入相同；採納版直接執行本次實作。兩份完整月份合成
資料與 Python／Tk 環境相同，不以另一台電腦或不同求解結果比較。

| 操作 | 2 PGY：原本 → 本次 | 混合案例：原本 → 本次 |
| --- | --- | --- |
| 內容未變的重新整理 | 214.4 → 8.7 毫秒 | 439.3 → 17.8 毫秒 |
| 實際鎖定／解鎖 callback | 223.1 → 16.4 毫秒 | 451.6 → 26.7 毫秒 |
| 日班內容改變後重畫 | 215.4 → 214.2 毫秒 | 448.9 → 437.4 毫秒 |

前兩項各組收益均遠大於本次組間波動；第三項未主張可證明的加速。
各組月曆文字／樣式、列表及統計快照一致。這項收益限於未改變卡片內容的更新，
不代表排班求解、首次啟動或所有使用操作都變快。日期、假日、月份、定案、
縮放、同一巢狀物件被修改及失敗後復原另由
[真實 Tk 回歸](../tests/test_roster_calendar_refresh_2026_10_09.py) 檢查。

本機原始 JSON、比較程序及逐筆快照摘要保存在私有量測證據中。
未受控的其他系統負載與 OS 磁碟快取仍是限制；沒有用這些數值推算 p95，
也沒有把環境或操作時間全部歸因為程式問題。

## 相容性、交付與院內待辦

本次只採納這一項 UI 改善；求解器已有優先目標提示，較慢案例的主要成本是
原有多目標最佳化，沒有修改醫師定案、排班品質、限制、求解時限或新增復原架構。
目前量測不足以支持第二項啟動／匯出／求解變更，保留原實作。

不更改磁碟設定 schema、班表或帳本格式；快照只存在分頁記憶體，關閉即釋放。
若需回退，使用既有完整版本回退流程恢復程式與 manifest 的一致版本，保留更新後
的班表、設定、帳本與其他業務狀態，不單独覆蓋一個來源檔。

本文件記錄量測及設計，不能替代獨立審查、指定 Claude 完整 diff 審查、
exact-SHA 候選 CI、同 SHA 正式 CI 或發佈後 smoke 證據。
真實 HIS、郵件、打卡、院內 DPI／視窗互動及完整版本回退驗收，仍依
[院內驗收清單](hospital_acceptance_template.md) 由使用者操作；本次未執行。
