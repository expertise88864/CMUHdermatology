**1. 同一輪多位病人完成時,間隔只有第一位拿到(高估平均看診時間)**

`newly_completed = current_completed_set - tracker['last_completed_set']` 是**集合**,
門診動態輪詢間隔 `CLINIC_LIGHT_REFRESH_SECONDS = 60` 秒,同一輪出現 2 位以上完成是常態。
原本的迴圈逐筆算 `doctor_pace = current_timestamp - tracker['last_valid_completion_time']`,
而且**在迴圈內**就把 `last_valid_completion_time` 更新成 `current_timestamp` →
集合迭代到的第一位拿到完整 300 秒,同批其餘拿到 0。

那些 0 會被 `duration_stats` 的中位數帶裁掉(所以平均不會直接歸零),但結果是
「兩人共用 300 秒」被記成**一筆 300** 而不是**兩筆 150** → 平均看診時間、
以及用它乘上候診人數的「預估剩餘」被系統性高估。

同一段還有第二個問題:`first_valid_skipped` 只跳過集合迭代到的第一位 ——
同批其餘拿著**同一個無效基準**算出的 0 照樣進了樣本。基準無效就該整批跳過。

修法:抽成 `clinic_state.apply_newly_completed(tracker, newly_completed, ts)`
純函式(與該檔既有的 `new_clinic_tracker` / `restore_tracker_from_state` 同層級),
先分類照光/有效,再把同一段間隔**平分**給整批有效完成;`first_valid_skipped`
未設時整批不取樣;`< 3600` 的休息/斷線門檻語意維持不變(對整段原始間隔判定)。

**2. `platform_win._admin_relaunch_params` 在 .exe 模式會把自己的路徑當引數傳給自己**

`run_as_admin` 用 `ShellExecuteW(None, "runas", sys.executable, params, ...)`,
params 原本是 `list2cmdline(sys.argv)` —— frozen(PyInstaller)模式下 `sys.executable`
就是程式本身、`argv[0]` 也是同一個 exe,於是變成
`app.exe "C:\...\app.exe" --background`。
同套件的 `paths.restart_self` 早就分兩種模式處理(frozen 時 `[sys.executable] + args`),
這裡沿用同一條規則。

⚠ **補審時請特別看這一項**:目前 repo 沒有 `.spec` 也沒有打包腳本,實務上跑 `.pyw`,
所以這是「與既有模式對齊的一致性修正」而非實機故障。若外審認為不該動提權路徑,可以撤回。
