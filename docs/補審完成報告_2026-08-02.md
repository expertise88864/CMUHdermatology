## 找到並修正的 11 條(全部獨立驗證為 CONFIRMED)

### 臨床/隱私影響最大的
1. **生日會被當成民國日期外送**(P1)。實機橫幅本來就含七位的生日 `0730623`,
   而日期正則是「任何獨立七位數」。院方只要把開頭日期改成西元八碼/斜線/暫時空白,
   生日就會被輸出到告警信與索引檔 —— 直接違反「生日一律不取」的核心承諾。
2. **定位掃描可能鎖住熱鍵約 1,000 秒**(P1)。而它【只在 HIS 沒回應時】觸發,
   那正是 400 控件 × 2.5 秒逾時會發生的條件。
3. **病歷號寫進沒有保存期限的一般 log**(P2)。`main.py` 早就明訂不得如此。
4. **F12 會讓整筆稽核紀錄消失**(P1)。加 F12 檢查是為了修 #2,卻讓
   `SubsystemInterrupted` 被上層廣義 except 吞掉 —— 醫師按取消,系統就把
   「剛剛寫錯了」一起忘掉。**加防護時沒想清楚例外會傳到哪裡。**

### 排班
5. `ColorRule` 用 `days[0]` 當週末代表日 → 拆段後限制套到週五那個人身上。
   實測:舊碼 `status=ok` 且同一人連值兩個同色週末。
6. 「無人可值」預檢要求同一人覆蓋整個原始區塊 → 兩人互補請假時誤擋整個求解。
7. `set_cell` 只在改週六時重排切片 → 改完週五後月檔/帳本/報告全是舊人選。
8. 月初 1 號是週六時,它的週五在上個月 → 正式路徑永遠看不到,連動失效。
9. 預覽(`render_report`)與定案結果可能不同 → 跨月週五收攏到唯一入口。

### 工具/設定
10. **push_helper 防還原有兩個空窗**,正是它聲稱要消除的事故類型;且自算 sha256
    與 git blob 因 CRLF 正規化必然對不上(會讓每一次推送都誤報)。改用 git blob id
    + index 比對 + 版本一致性檢查。
11. **還原預設寫入失敗會先刪掉正式設定檔**;改用複製後又發現 `copy2` 不是原子的
