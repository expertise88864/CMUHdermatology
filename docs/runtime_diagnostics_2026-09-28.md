# 會診與打卡執行摘要（2026-09-28）

兩個設定視窗的「執行摘要（唯讀）」每三秒在背景讀取一次本機紀錄。開啟或刷新摘要不會啟動 HIS、SMTP、Outlook 或打卡網站，也不會改變寄送或點擊決策。診斷事件只用來說明流程；會診寄送結果仍以原有寄送帳本為準，打卡完成與待確認仍以原有每日持久化狀態及官方紀錄為準。

## 狀態定義

| 程式 | 畫面狀態 | 意義與後續動作 |
| --- | --- | --- |
| 會診 | 查詢失敗 | HIS 查詢未取得可用結果；人工核對 HIS。 |
| 會診 | 名單未知 | 查詢完成，但名單無法可靠解析；不能當成空名單，人工核對 HIS。 |
| 會診 | 確定空名單 | 成功讀取且名單為空；不代表查詢失敗。 |
| 會診 | 寄送待確認 | 帳本仍為 prepared、submitting 或 unknown；可能已被寄送端接受，先核對寄件備份，勿直接重寄。 |
| 會診 | 另有無帳本寄送待確認 | 某次寄送結果不明，可能是當次帳本建立失敗，或使用沒有寄送帳本的 Outlook 模式；後一輪成功不能證明前一輪未送達。保留人工核對寄件備份的提示；帳本建立失敗時另提示檢查本機儲存。 |
| 會診 | 另有無帳本確認拒收 | 某次寄送已回報收件人拒收，但當次帳本建立失敗；後一輪成功不能取代該次收件設定與本機儲存的檢查。 |
| 會診 | 部分收件人確認拒收 | 部分收件人已被接受，且帳本另有明確的永久拒收紀錄；檢查收件設定與既有補寄紀錄。 |
| 會診 | 部分送達／其餘未送達 | 帳本顯示部分收件人已被接受，但其餘尚無送達依據；檢查執行紀錄。 |
| 會診 | 未送出／寄送失敗 | 帳本整筆失敗；可能是連線或認證等寄送問題，不能單憑此狀態宣稱收件人拒收。 |
| 會診 | 寄送端接受 | SMTP 或 Outlook 呼叫已接受，**不保證收件匣已送達**。帳本可能在後續核對後更新。 |
| 會診 | 另有寄送待確認／部分未送達／寄送失敗 | 即使最新一筆已成功，較早且未被新寄送接手的帳本紀錄仍需分別核對。 |
| 會診 | 另有帳本狀態無法判讀 | 較早且仍有效的寄送紀錄含異常狀態；最新一筆成功不能代表這筆已結案，須檢查本機帳本並核對寄件備份。 |
| 會診 | 較早待處理寄送紀錄過多 | 摘要最多逐筆核對最近 256 筆較早且尚待處理的紀錄；超過上限時提示人工核對原帳本。較早且已確認的寄送以彙總查詢取得最後成功時間，不會單因筆數多就要求人工檢查。 |
| 會診 | 最後成功：已確認寄送，但先後不明 | 較早寄送的確認時間晚於較新寄送，或其確認紀錄無法判讀；不能由帳本列順序推定最後成功。若另有獨立且已完成的診斷成功事件，仍顯示該事件時間；必要時核對原帳本。 |
| 會診 | 寄送狀態不明 | 既有寄送帳本無法讀取；不能當成沒有寄送紀錄，須檢查本機儲存並核對寄件備份。若僅暫時被其他程序鎖定，畫面會提示稍後重試，仍不可直接重寄。 |
| 會診／打卡 | 診斷紀錄無法讀取 | 診斷資料庫損毀或無法存取；畫面仍顯示可讀的寄送帳本或打卡持久化狀態，但不能把診斷紀錄當成空白。暫時被鎖定會另提示稍後重試。 |
| 會診 | 解析紀錄無對應流程結果 | HIS 解析背景工作有紀錄，但當次查詢主流程結果未能保留下來；不以解析成功取代其他批次的查詢失敗，須檢查本機儲存並人工核對 HIS。 |
| 會診 | 診斷順序不明 | 診斷資料庫曾因短暫忙碌或儲存問題未記下一步，後續寄送接受紀錄與另一批 HIS 查詢失敗的先後無法確定；兩者都顯示並請人工核對 HIS。只有明確的儲存失敗才另提示檢查本機儲存。 |
| 會診／打卡 | 系統時間異常 | 紀錄時間互相矛盾或落在未來；先核對電腦時鐘，寄送與打卡結果仍以帳本及官方紀錄為準。 |
| 打卡 | 讀取不明 | 網站紀錄無法可靠讀取；不以「沒有紀錄」推論應再次點擊。 |
| 打卡 | 無官方紀錄 | 官方紀錄已成功讀取，該時段尚無打卡。 |
| 打卡 | 點擊待確認 | 已進入點擊流程，但尚未從官方紀錄確認；原有持久化保護會阻止重複點擊。 |
| 打卡 | 官方已確認 | 重新讀到符合時段的官方紀錄；這才是完成依據。 |
| 打卡 | 部分帳號未確認 | 同一輪多帳號排程中，至少一個帳號沒有官方完成依據，包含宣告由另一行程持有而略過的帳號；檢查網站紀錄與既有告警。 |
| 打卡 | 略過 | 本輪全部帳號未取得執行權，且沒有後續持有者結果可核對；至官方系統確認，勿重複點擊。 |
| 打卡 | 診斷順序不明 | 診斷資料庫曾暫時拒絕寫入，無法由剩餘事件確定不同批次的先後；若同日另有失敗，仍顯示其處理指引並請至官方系統核對。 |
| 打卡 | 持久化狀態不明 | 今日狀態檔無法讀取；已確認、待確認及帳密錯誤數量均不明，須檢查本機儲存並至官方系統核對。 |

畫面顯示最近觀察的階段、狀態時間、最後成功時間、資料新鮮度、錯誤分類和人工處理原因。會診的階段觀察與最新寄送帳本分別呈現；只有時間重疊不足以證明兩筆紀錄屬於同一輪，因此不會用別筆帳本成功清除本輪的逾時、拒收或儲存警示。會診超過 20 分鐘、打卡超過 5 分鐘的「進行中」觀察會標為過期；跨日打卡狀態不沿用到新一天。若今日沒有狀態檔，顯示「尚無狀態檔」而不推論為零次；若檔案損毀或無法讀取，數量顯示不明。舊版每日打卡狀態檔只存日期，不存每筆精確時間，因此若只有舊狀態檔、沒有診斷事件，畫面上的時間是狀態檔更新時間，不可解讀為官方打卡時間。

## 畫面與耗時範例

以下是**合成資料**示例，不是醫院 HIS、SMTP、Outlook 或打卡網站的實測：

```text
階段：寄送核對｜狀態：寄送待確認｜查詢結果：名單已讀取
狀態時間：09/28 12:41:03｜資料：最新（0 分鐘前）
最後成功：09/28 09:02:11｜錯誤分類：無
人工處理：請核對寄件備份，勿直接重寄
最新寄送：寄送待確認（09/28 12:41:03；接受 0／暫拒 0／永久拒收 0／不明 1）

階段：官方紀錄確認｜最近觀察：點擊待確認
狀態時間：09/28 07:35:12｜資料：最新（1 分鐘前）
最後官方確認：無紀錄｜錯誤分類：無
人工處理：請至官方系統確認，勿重複點擊
今日持久化：已確認 0／點擊待確認 1／帳密錯誤 0
```

安全診斷摘要中的耗時使用單調時鐘記錄。合成事件格式例如：

```text
query ok 2340ms none none
parse ok 340ms none none
redact ok 4ms none none
send pending 60000ms timeout verify_delivery
website ok 820ms none none
login ok 420ms none none
read no_record 140ms none none
confirm official_confirmed 670ms none none
```

事件只允許固定的階段、結果、錯誤及人工處理代碼和整數毫秒，最多保留 256 筆，正常時鐘下保存 7 天；高頻事件可能使較早的中間步驟提前淘汰，但會保留期限內最近一次成功事件與關鍵待處理狀態。系統時間大幅倒退時，已記錄的無帳本待確認警示不會因看似「未來」而立即刪除；新事件不繼承該未來時間。另保留有限的執行批次順序，以免舊結果重新顯示為最新，畫面會提示核對系統時鐘。事件沒有姓名、病歷號、帳號、信件內文、密碼、token、原始畫面或例外文字。匯出的白名單事件不含絕對時間；設定視窗仍以本機紀錄呈現狀態時間。安全診斷匯出沿用既有匯出器；會診摘要不納入可能含歷史資料的原始 log。打卡匯出另含既有已去敏的 log 與除錯文字檔，匯出前仍須人工檢查內容。

## 醫院電腦驗收清單

1. 在設定視窗開啟摘要後觀察 HIS／Outlook／SMTP 與打卡網站，確認沒有因「查看」多出查詢、寄信或點擊。
2. 用實際排程在無病人、名單讀取失敗及正常有會診三種情境，核對摘要和既有 log、寄送帳本；勿把病人資訊貼入診斷回報。
3. 在可控環境下觀察寄送逾時與部分拒收，確認帳本狀態、補寄與畫面一致；逾時時先查寄件備份，不直接重寄。
4. 打卡時核對「讀不到紀錄」「已點擊未確認」「官方已確認」的轉換；重啟後待確認狀態仍在，不能再次點擊。
5. 隔天重新開啟設定視窗，確認昨日打卡完成或待確認不會被標成今日結果。
6. 匯出安全診斷摘要並檢視壓縮檔內容：會診應只有白名單代碼與耗時；打卡另有既有已去敏的 log 與除錯文字檔。若要回報問題，仍須先自行檢查檔案內容。

上述項目需要在院內實機驗證。自動測試使用 fake HIS、SMTP、Outlook、portal、時鐘和暫存檔，不能替代實機驗收。
