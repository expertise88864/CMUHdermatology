# P2-06：main.py 分層施工計畫

外審原文：「main.py 約 17,000 行，缺乏分層」。這是**多週**的工作，不可能一次做完，
所以先把它切成可以獨立上線、獨立回滾的刀。本檔記錄**量出來的現況**與切法，
接手的人從「下一刀」往下做即可。

範本是 `src/cmuh_common/roster/`（model / rules / solve / service / storage / ui / export），
已經是這個 repo 自己驗證過的分層形狀。

| 指標 | 數字 |
| --- | --- |
| main.py 行數 | **15,902**（原 17,519，累計減 1,617 行） |

量測腳本的作法：用 AST 找出每個頂層函式引用到的**模組級全域**數量。
引用數 0 的就是「可以直接搬走的葉子」；引用數愈高愈晚搬。
（`check_appointment_count` 441 行、引用 41 個全域 —— 但**組成**才是重點：23 個常數、
29 個函式呼叫、可變狀態只有 2 個。見第四刀(a)。）

## ★鐵律：每一刀都要帶測試★

分層會把行數從 `entrypoints` 層搬到 `shared` 層，而 `coverage_floors.json` 的
`shared` 門檻只有約 1 個百分點的餘裕。**搬一批沒測試的程式碼進 shared，門檻會（正確地）
把它擋下來。**

第一刀實測：那 15 個函式在 main.py 裡只有 **17.9%** 的語句被覆蓋到；
直接搬過去會讓 shared 從 72.5% 掉到 71.4%（低於門檻）。補了測試（88.8%）之後
反而升到 74.2%。

這不是額外的負擔，這是分層的**理由**：搬到獨立模組才測得到。

## 刀法

### ✅ 第一刀（2026-07-31 完成）：HIS 視窗／控制項 Win32 原語

`src/cmuh_common/his_window.py`，15 個函式、427 行。
`tests/test_his_window_2026_07_31.py` 48 支。

選它先做的理由不是行數，是**風險**：這一層正是本 repo 反覆出事的地方
（`IsWindow` vs `IsWindowVisible`、同 class 對話框誤判、殘留舊視窗），
而它在 main.py 裡時判斷邏輯**一行測試都沒有**。集中之後才有一個地方可以加固。

作法（後續每一刀照抄）：
1. 函式原文＋註解**一字不刪**搬過去（註解裡的 `[日期 來源]` 都是踩過的坑）。
2. 加測試接縫：`_user32()` / `_kernel32()` / `_imm32()` 取得器取代散落的
   `ctypes.windll.user32`。**這是唯一的行為面改動**，呼叫的 API、順序、回傳語意照舊。
3. main.py 用 `from ... import 新名 as 舊私有名` —— **只搬家、不改呼叫端**
   （內部 100+ 個呼叫點、tests/ 多支直接用 `main._find_window_...`）。
4. 補測試到覆蓋率不退步為止；跑 `check_coverage.py --update` 把欄杆提上來。

### ✅ 第四刀(a)（2026-08-01 完成）：reg52 HTML 解析器

★**這一刀推翻了本計畫書原本的建議**★
