# 批次 Z 下半：UNKNOWN 的暫時性抑制（設計）

對應外審 P1-03。**本文件是動工前的設計與約束，尚未實作。**

---

## 1. 問題

`main.py` 的止掛提醒寄信：

```
DeliveryOutcomeUnknown
  → ledger.settle(unknown=True)
  → helper return True
  → caller _mark_alert_email_sent(nk)      ← 寫【永久】去重記號
```

批次 U 加了 UNKNOWN 回查之後，前提變了：

```
回查 → 寄件備份【查無】 → ledger.resolve_unknown(delivered=False)
     → 帳本說「可以重寄」
     但 alert_email_sent.json 說「已寄過」
     → marker 贏 → 那一則止掛提醒【永遠不會再寄】
```

**兩個真相來源互相矛盾，而錯的那個贏。**

## 2. ★為什麼不能只把 marker 拿掉★

現行 `return True` 是外審定案過的取捨，理由寫在 `main.py` 的註解裡：

```
回 False → 呼叫端釋放寄送權 → 下一輪掃描再寄 → 醫師每輪收到重複提醒
```

只把 marker 拿掉 ＝ 把「少數情況漏一則」換成「每輪重複寄」。
**那比現況更糟**，而且是這個 session 反覆踩到的形狀
（見 `a-fix-can-be-worse-than-the-bug`）。

需要的是**第三種狀態**：不重寄、但也不宣稱已送達。

## 3. 設計

### 3.1 不動既有格式
`alert_email_sent.json` 的值是日期字串，載入/存檔走
`_alert_records_for_save` / `load_alert_email_sent`（那支才剛修過
「讀不到不可以覆蓋」）。改它的值結構會牽動那條已驗證的路徑。

**另開 `alert_email_pending.json`**：

```json
{ "<notify_key>": { "since": "2026-08-09T10:00:00",
                    "message_id": "<...>",
                    "business_key": "alert:<nk>" } }
```

### 3.2 狀態轉移（封閉集合）

| 事件 | 動作 |
| --- | --- |
| SMTP 結果 UNKNOWN | 寫 **pending**（不寫永久 marker） |
| 判斷「寄過了嗎」 | 永久 marker **或** 未逾期的 pending → 都算寄過 |
| 回查：寄件備份**查到** | pending → **升級**成永久 marker，刪 pending |
| 回查：寄件備份**查無** | **刪 pending** → 下一輪允許重寄 |
| 回查：**查不出來** | 不動（下一輪再試） |
| pending 超過 `PENDING_MAX_AGE`（建議 6 小時） | **告警 + 刪 pending** |

### 3.3 ★最後一條是關鍵★

IMAP 長期不可用時，回查**永遠拿不到答案**。沒有出口的話，這個機制會從
「防重複」變成**永久靜默漏寄** —— 正是 2026-08-05 事故那個形狀
（沒有出口的 fail-closed）。

所以 pending 逾期時：
* 寄一封告警給開發者（說明「這一則止掛提醒結果不明超過 N 小時，
  已解除抑制，下一輪會重寄；若醫師已收到，會收到第二封」）
* 刪掉 pending，讓正常流程接手

**寧可讓人收到一則重複，也不要讓一則該寄的永遠不寄而且沒人知道。**

## 5. 驗收準則（每一條都要有測試 + 突變）

1. UNKNOWN → **不寫**永久 marker、**有**寫 pending。
2. pending 存在期間 → **不重寄**。
3. 回查查到 → 升級成永久 marker，pending 消失。
4. 回查查無 → pending 消失，下一輪**會重寄**。
5. 回查查不出來 → pending 不動（三態不可摺成兩態）。
6. pending 逾期 → **告警**且解除抑制（★不可以無限抑制★）。
7. pending 檔讀不到 → **不可以**當成「沒有 pending」而重寄；也不可以
   當成「有 pending」而永遠不寄 —— 呼叫端必須自己決定並留紀錄。
8. 跨重啟：pending 要活得下來（否則重啟就等於解除抑制）。
9. **反方向**：正常成功的路徑不可以因此變成 pending。
