## 可疑處（請重點看這裡）

1. **noqa 會不會擴散**：`test_the_noqa_sites_are_where_we_verified_them` 釘住 noqa 只
   能出現在核對過的三個檔案，但它是**檔案層級**的白名單 —— 同一個檔案裡新增的 noqa
   不會被擋。這是已知的鬆度。
2. **`test_the_verified_sites_are_still_synchronous` 是【結構釘位】不是語意證明**：
   它檢查 `fut_m.result()` / `re.sub(` 還在。若有人改寫成別的同步 join 寫法，這支會
   誤紅；若有人保留這些字串但在別處改成跨迴圈收集，這支會漏。作用是提醒回頭重判，
   不是保證。
3. **掃描器排除自己**：`_b023_noqa_lines()` 用 `__file__` 排除本測試檔（該檔在
   *談論* noqa 而非 *使用* 它）。本輪已經因為「比對原始碼被自己的說明騙過去」踩過
   好幾次，這裡是刻意處理過的，但排除自己本身也是一種盲點。
4. **`--select B023` 覆寫的語意**：多支測試用
   `ruff check --config <repo ruff.toml> --select B023 <tmp file>`。若 `--select`
   與設定檔的交互不如預期（例如 noqa 處理被改變），這些測試可能量到的不是 repo 的
   實際行為。
